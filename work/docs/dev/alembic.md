# 📦 Alembic Migration System

## 📌 Overview

This project uses **Alembic** as the database migration tool for managing schema changes in a controlled, versioned and reproducible way.

All database schema modifications MUST be performed through migrations. Direct manual changes to the database schema are strictly prohibited in development, staging, and production environments.

---

# 🏗️ Architecture

## 📁 Migration Structure

All Alembic-related files are located in:

```
work/scripts/db/migrations/
```

Structure:

```
migrations/
│
├── env.py                  # Alembic runtime configuration
├── script.py.mako          # Migration template
├── README                  # Alembic autogenerated info
│
└── versions/               # All migration revisions
    ├── 010a086dd963_init_schema.py
    ├── 14128badc72a_remove_unique_constraint_from_trade_date.py
```

---

## 🧱 Database Models Location

All SQLAlchemy models are defined in:

```
work/scripts/db/models/
```

Example:

```
stock_quote.py
```

Base declarative class:

```
work/scripts/db/base.py
```

---

## 🔌 Database Connection

Database session and engine are defined in:

```
work/scripts/db/session.py
```

Connection is configured via:

* `.env` (primary source for credentials)
* `work/config/app_config.json` (non-sensitive runtime config)

# ⚙️ Workflow

## 📌 1. Create a new migration

Use automated tooling:

```bash
setup\db\alembic_revision.bat "add stock quotes table"
```

Equivalent raw command:

```bash
alembic revision --autogenerate -m "add stock quotes table"
```

### 🔥 Important rules:

* Message MUST be descriptive
* Use snake_case or natural language
* Never include SQL manually in revision name

---

## 📌 2. Apply migrations

```bash
setup\db\alembic_upgrade.bat
```

Equivalent:

```bash
alembic upgrade head
```

---

## 📌 3. Rollback migrations

Step back one revision:

```bash
setup\db\alembic_downgrade.bat -1
```

Rollback to specific revision:

```bash
setup\db\alembic_downgrade.bat <revision_id>
```

---

## 📌 4. Check current migration state

```bash
setup\db\alembic_current.bat
```

---

# 🧠 Core Principles

## 1. Migrations are immutable

Once a migration is created and committed:

* ❌ DO NOT modify it
* ❌ DO NOT delete it
* ✔ Create a new migration instead

---

## 2. Autogenerate is mandatory

All migrations MUST be generated using:

```bash
alembic revision --autogenerate
```

Manual SQL migrations are forbidden unless explicitly required.

---

## 3. Schema consistency rule

All schema changes must be reflected in:

* SQLAlchemy models (`models/`)
* Alembic migration (`versions/`)
* Database state

---

# 🧾 Naming conventions

## Table naming

* snake_case
* plural preferred

Example:

```
stock_quotes
market_data
trading_sessions
```

---

## Column naming

* snake_case only
* no abbreviations unless standard (e.g. id, utc, etc.)

Example:

```
trade_date
open_price
close_price
volume
```

# After model changes:

Always:

1. Modify SQLAlchemy model
2. Generate migration
3. Review generated SQL
4. Apply migration locally
5. Commit both model + migration
